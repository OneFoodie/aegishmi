# 02 概要设计（HLD）

> 项目：AegisHMI　版本：v0.1.0

---

## 1. 总体结构

采用四层结构，依赖方向自上而下，业务层不反向依赖界面：

```
┌────────────────────────────── UI 层（主线程）──────────────────────────────┐
│ MainWindow（连接面板 + 日志）  WaveformView（自绘波形）                       │
│ TestPage（流程加载/执行/结果）  HistoryPage（历史查询/导出）                   │
└───────────────▲───────────────────────────────────────────▲────────────────┘
                │ 信号槽（跨线程用 Qt::QueuedConnection）      │ 直接调用
┌───────────────┴──────────────── Service 层 ────────────────┴────────────────┐
│ DeviceService：连接管理 / 帧解析 / 采样入环 / 命令应答 / 统计                 │
│ TestEngine：流程状态机（command/delay/measure、重试、中止）                   │
│ TestRepository：SQLite 运行记录与步骤、CSV 导出                              │
└───────────────▲───────────────────────────────────────────▲────────────────┘
                │ 纯 C++ 接口（ITestDevice / IRepository）     │
┌───────────────┴──────────────── Infra 层 ──────────────────┴────────────────┐
│ TcpTransport  SerialTransport  ModbusTcpClient  ModbusRtuClient  OpcUaClient │
└───────────────▲───────────────────────────────────────────▲────────────────┘
                │ 字节流 / 寄存器 / 节点值                     │
┌───────────────┴──────────────── Protocol / Core 层 ────────┴────────────────┐
│ FrameCodec（粘包分包 + CRC）  Frame 类型与负载编解码  Modbus 编解码           │
│ SpscRingBuffer（无锁环形缓冲）  CRC16                                        │
└─────────────────────────────────────────────────────────────────────────────┘
```

外部：`aegis_sim` 独立进程，提供 9527（自定义协议）、5020（Modbus TCP）、4840（OPC UA）。

## 2. 线程模型

```
主线程（UI）
 ├─ DeviceManager（QObject）：N 台设备的创建/连接/状态聚合
 ├─ DeviceService × N（QObject，住主线程）：各自收包解析、采样入环、统计
 ├─ TestEngine：在独立 QThread 中顺序执行步骤（阻塞等待窗口结束不影响 UI）
 ├─ WaveformView：50 ms 定时器取"当前选中设备"的环 → 像素桶聚合 → 一次性重绘
 └─ MainWindow：设备列表、状态/日志刷新、按钮交互

通信线程 thread_ × N（每台设备一条）
 ├─ TcpTransport（QTcpSocket）
 ├─ ModbusTcpClient（QTcpSocket，20 ms 轮询）
 ├─ ModbusRtuClient（QSerialPort，50 ms 轮询）
 └─ OpcUaClient（UA_Client，订阅 + 写节点）
```

规则与原因：

- 通信对象 `moveToThread(thread_)`，socket/串口只在所属线程读写（Qt 的 socket 非线程安全）；
- 子线程发出的信号统一用 `Qt::QueuedConnection` 投递回主线程，业务逻辑无需加锁；
- `sendCommand` 在引擎线程阻塞等待 Ack（`std::condition_variable` + 超时），
  主线程收到 Ack 后唤醒，保证 UI 不阻塞；
- 界面刷新用固定 50 ms 定时器（20 fps），避免"来一帧画一次"造成 CPU 抖动。

数据流（自定义协议）：

```
QTcpSocket(子线程) → bytesReceived(队列) → DeviceService::onBytes(主线程)
    → FrameCodec 拆帧 → decodeDataPayload → ChunkRingBuffer（块 = 时间戳 + N 通道 int16）
    → MainWindow::onTick(50ms) → 逐块取出 → 按像素桶 min/max 聚合 → WaveformView
```

## 3. 模块职责

| 模块 | 主要类 | 职责 | 不做什么 |
|---|---|---|---|
| protocol | FrameCodec / Frame / Modbus | 帧格式与编解码、CRC、异常码 | 不碰 socket |
| core | SpscRingBuffer / ChunkRingBuffer / DeviceConfig | 无锁队列（单点/分块）、通道配置 | 不做业务判断 |
| core | StationConfig | 工位/线体/治具/SN 规则/MES 参数 | 不做界面
| infra | TcpTransport / SerialTransport | 字节流收发、连接状态 | 不解析业务负载 |
| infra | ModbusTcpClient / ModbusRtuClient | 轮询寄存器、写寄存器、事务号匹配 | 不做单位换算 |
| infra | OpcUaClient | 连接端点、订阅节点、写节点 | 不实现服务端方法调用 |
| service | DeviceManager | 多设备清单、连接分发、状态/日志聚合 | 不做协议解析 |
| service | DeviceService | 组合传输 + 解码 + 采样 + 命令应答 | 不画图、不存库 |
| service | AlarmMonitor | 消费秒级摘要，按阈值 + 回差产生/恢复报警 | 不做界面展示 |
| service | MesUploader | 结果 JSON 入队、异步 POST、退避重试 | 不做业务判定 |
| security | AuthService | 登录鉴权、角色权限、审计写入 | 不做界面布局 |
| quality | spc | Cp/Cpk、I-MR 控制限、判异规则（纯函数） | 不访问数据库与界面 |
| test | FlowLoader / FlowValidator / FlowCatalog / TestEngine | JSON 加载校验、方案库扫描、执行状态机（含 script） | 不直接访问 UI |
| storage | TestRepository / SummaryWriter | 运行记录、步骤、CSV、SPC 数据源、Andon、交接班、追溯检索、秒级摘要 | 不计算判定结果 |
| storage | SystemRepository | 用户（含启用状态）、审计、报警事件三类系统表 | 不做业务判定 |
| ui | MainWindow / WaveformView / TestPage / HistoryPage / AlarmPage / AuditPage / DashboardPage / SpcPage / ShiftPage / UserPage / SopDialog / LoginDialog | 展示与交互 | 不做通信与解析 |
| ui | pdf_report | 用 QPdfWriter + QTextDocument 生成审核报告 | 不做数据查询以外的事 |

## 4. 关键设计决策

### 4.1 波形改为自绘（QWidget + QPainter），不用 QChart

- 旧实现：`QLineSeries::append` + 图表全量重绘，10 kHz 下每帧耗时约 **800 ms**，界面卡死；
- 新实现：按"每个像素一个时间桶"聚合 min/max，每桶只画谷/峰两点 → `QPolygonF` 一次性绘制；
- 关键细节：画笔必须 `setWidth(1)` + `setCosmetic(true)`。非整数宽度会触发 QStroker 矢量描边，
  直接把单帧从 2.7 ms 拖到 800 ms（gdb 显示卡在 `QRasterPaintEngine::drawPolygon`）。

### 4.2 分块无锁环形缓冲（Chunk）

- 生产者（收包线程/主线程解析）与消费者（UI 定时器）各自只改一个索引，仍是 SPSC 无锁；
- 一个 Chunk = 一帧的连续 int16 数据（时间戳 + 点数 + N 通道），运行期只 memcpy，
  不再为每个采样点构造结构体；
- 槽位预分配：256 槽 × 512 点 × N 通道 × 2 B，32 通道约 8 MB、6 通道约 1.5 MB；
- 容量取 2 的幂，`index & (Capacity-1)` 代替取模；满时 `push` 返回 false，上层累计丢块。

### 4.3 协议以"模式"而非"插件"扩展

`ConnectionMode { CustomProtocol, ModbusTcp, ModbusRtu, OpcUa }` 由 DeviceService 统一切换：
切换时先关闭其它链路，避免两条链路同时占用设备；命令语义在各模式下做映射。
（插件化 `QPluginLoader` 是后续演进方向，当前规模不值得引入。）

### 4.4 采样率对被抽象出来

`ITestDevice::sampleRateHz()` 返回当前协议的实际采样率：
自定义协议取设备配置、Modbus TCP 50 Hz、RTU 20 Hz、OPC UA 10 Hz。
测试引擎用 `expected = windowMs × rate / 1000` 判断数据是否足够，避免固定用 10 kHz 误判低速率协议。

### 4.5 命令/应答用条件变量而不是信号槽同步

`sendCommand` 需要"发出去 → 等结果"的同步语义，放在引擎线程执行；
主线程收到 Ack 后置位并 `notify_all`。这样既保证顺序，又不在 UI 线程阻塞。

### 4.6 测试替身优先

`ITestDevice` 抽象让引擎可以用 Mock 设备测试超时/失败/重试；
`tst_deviceservice` 里用进程内假设备/假 Modbus 服务端验证真实链路，避免依赖外部进程与端口。

### 4.7 OPC UA 用订阅（Subscription/MonitoredItem）而不是轮询

- 旧做法：每 100 ms 对 6 个节点各发一次 Read 请求（6 请求/100 ms，且多数值没变化）；
- 现做法：建 1 个 Subscription + 6 个 MonitoredItem，服务端只在值变化时推送；
  客户端用 10 ms 定时器 `UA_Client_run_iterate` 处理 Publish 响应，每 100 ms 把缓存快照交给上层；
- 收益：请求数从 60 次/秒降到接近 0（仅 Publish 心跳），带宽与设备 CPU 明显下降；
- 写设定值：`UA_Client_writeValueAttribute` 直接写节点 0/1，与 Modbus 写共用"事务号 + 条件变量"的应答等待机制；
- 缺失节点容错：某个 MonitoredItem 创建失败只记录错误，不阻断其它通道（该通道读数为 0）。

### 4.8 通道数/采样率配置化（P1）

- `core::DeviceConfig` 从 `configs/devices/active.json` 读取 channelCount / sampleRateHz / 通道名；
  搜索顺序：环境变量 `AEGIS_DEVICE_CONFIG` → exe 同目录 configs → 开发目录 configs → 默认 6 通道；
- 协议层不再依赖固定 6：DATA 帧长度上限从 4 KB 提到 64 KB，解码按配置的通道数校验整除关系；
- 分块缓冲按配置分配（256 槽 × 512 点 × N 通道），32 通道约 8 MB，避免逐点结构体膨胀；
- 模拟器与上位机读同一份配置，保证两端通道数一致；不一致时上位机记录并丢弃不匹配的帧。

### 4.9 多设备并发（P2）

- `DeviceManager` 读取 `configs/devices/fleet.json`，每台设备创建独立 `DeviceService`
  （独立通信线程 + 独立分块缓冲），互不阻塞；
- 对外信号统一带 `deviceId`（连接状态、日志），界面按 id 更新设备列表；
- 波形/统计只显示"当前选中设备"：切换时清空波形并重建通道（不同设备通道数可能不同）；
- 自动测试通过 `DeviceProxy` 转发到当前设备，切换设备无需重建引擎线程；执行期间锁定切换；
- 模拟器支持 `--port / --modbus-port / --opcua-port / --config`，多进程即可模拟多台设备；
  `scripts/demo_multi_device.bat` 一键启动 2 台模拟器 + 上位机。

### 4.10 存储分层（P3）

- 原始 10 kHz 波形只留在内存（约 2.5 秒），不落盘：一条 32 通道数据流一天就是几十 GB；
- 落盘的是"每秒摘要"：`sample_summary(device_id, channel, epoch_sec, min/max/avg/count)`；
- 聚合在收包路径完成（每点 3 次比较/累加），不额外遍历；
- `SummaryWriter` 独立线程攒批（500ms 或 500 行）单事务提交，避免 UI 线程每秒抖动；
- 保留 7 天，启动时清理；趋势页按设备/通道/时间范围查询（60 分钟仅 3600 行/通道）。

### 4.11 本地账号 + 权限点，而不是把角色判断散到界面

- 所有账号存本地 `app_user` 表：随机盐 + 1 万轮 SHA256，不存明文；
- 权限抽象为 `View / Operate / Administer` 三个权限点，界面只问"能不能做这件事"，
  不直接写 `if (role == admin)`，后续增加角色不需要改每个控件；
- 观察员禁用连接/测试/确认/导出；审计页只对管理员可见。

### 4.12 审计与报警共用 SystemRepository

- 审计（audit_log）和报警（alarm_event）都是"系统事件"，与测试记录（test_run）职责不同，
  但共用同一个 `aegis.db`；`SystemRepository` 独立连接，避免与摘要写线程互相阻塞（WAL + busy_timeout）；
- 审计只追加、不修改；报警一条记录覆盖"进入 → 恢复"的完整生命周期，确认状态也落在这条记录上。

### 4.13 报警用秒级摘要 + 回差，而不是逐点判定

- 判定输入是 `DeviceService` 已有的每秒摘要（avg），不额外遍历 10 kHz 原始数据；
- 每个设备/通道维护 正常/高/低 三态，恢复需要回到阈值内侧 `deadband`，避免噪声导致反复报警；
- 报警判定在主线程消费摘要信号，不新增线程；写入失败不影响监控主链路。

### 4.14 脚本步骤用 QJSEngine，限制在"设备操作"范围内

- `script` 步骤在引擎线程内创建 QJSEngine，暴露 `setVout/setIout/measureAvg/sleep/log`；
- 不挂载文件、网络等扩展能力，脚本只能操作当前测试设备，降低误用风险；
- 设备操作失败在 C++ 侧记录第一条错误，脚本即使忽略返回值也会判失败，避免"静默通过"；
- 每个脚本步骤独立引擎，变量不会串到下一步。

### 4.15 工单 + SN 防呆作为产线最小闭环

- 工单是产线数据的组织单位：运行记录带 `work_order`，看板按工单聚合；
- 防呆放在"开始测试"前：工单必选、SN 正则校验、同工单同 SN 重复需确认；
- 复测不新建产品，只在运行记录上标 `retest=1`；FPY 按"每个 SN 首次判定"计算；
- 当前工单持久化在 QSettings，重启恢复；测试运行期间锁定工单切换。

### 4.16 MES 上传用本地 outbox，而不是同步等待

- 测试结束先落本地库，再生成 JSON 写入 `mes_outbox`；上传成功与否不影响测试结论；
- 断网/重启后继续处理 PENDING；失败指数退避，达上限转 DEAD，支持人工重传；
- HTTP 交互在 UI 线程异步完成（QNetworkAccessManager），不阻塞界面与采集。

### 4.17 质量闭环用状态机 + 派生统计，尽量少建表

- 首件检验状态放在 `work_order`（PENDING/WAITING/CONFIRMED/REJECTED），由运行结束事件推进；
- 不良原因只加 `test_run.fail_reason` 一列，看板按原因聚合，不单独建原因表；
- 返修/复测不新建流程：`retest=1` 已有，"待返修/复测通过"从运行记录派生；
- 治具单独 `fixture_usage` 表（按治具累计次数与校准到期），测试前校验、落库后计数。

### 4.18 SPC 计算做成纯函数，界面只负责取数与绘图

- `quality::spc` 输入 `QVector<double>` + 规格限，输出均值/σ/Cp/Cpk/I-MR 控制限/判异列表；
- 不依赖数据库、Qt Widgets，可用 `tst_spc` 直接验证公式与边界（单点、零波动）；
- 界面（`SpcPage`）只做三件事：查 `spcItems/spcPoints`、调 `compute`、把结果画出来；
- 判异规则选 Nelson 常用子集（越限、7 点同侧、6 点趋势、3 点中 2 点超 2σ），
  足够覆盖现场常见异常，又不会因规则过多导致误报。

### 4.19 规格限随运行落库，而不是查询时回读流程文件

- `test_step` 增加 `min_limit / max_limit`，`saveRun` 从流程 `expect` 一并写入；
- 换配方、改限值后，历史数据的 Cp/Cpk 仍按当时的配方计算，避免"追溯失真"；
- SPC 以 `flow_id + step_id` 聚合，同一工单多个方案的同名步骤不会混在一起。

### 4.20 SOP/资质/班次/Andon 全部走 station.json，不新增独立配置体系

- 这些参数都是"这台工位"的属性，和已有的线体/治具/MES 放在同一份文件，换线只改一处；
- SOP 按产品精确匹配优先，其次 `"*"` 通用条目；资质同理，缺失即不限制，避免演示环境被卡死；
- 读取沿用既有的搜索顺序（环境变量 → dist/configs → 开发 configs），无需改动部署脚本。

### 4.21 Andon 是"落库后判定 + 持久化事件"，不是内存标志

- 判定发生在每次运行落库之后：连续 FAIL 次数与 FPY 都是 SQL 聚合，不在界面心算；
- `andon_event` 一次停线一条记录，`cleared_at` 为空表示仍在停线，重启后依然锁定；
- 解除需要管理员权限并写审计；界面只展示状态，不参与判定，避免绕过。

### 4.22 PDF 报告用 QPdfWriter + QTextDocument，不引入打印对话框

- 报告内容是 HTML 表格，`QTextDocument::print(QPdfWriter*)` 直接输出 A4 PDF；
- `QPdfWriter` 属于 Qt6::Gui，不需要额外 PrintSupport 模块，dist 依赖更少；
- 批量报告用单个文档 + `page-break-before`，避免多文档合并 PDF 的额外依赖；
- 生成前先探测目标路径可写，生成后校验文件非空，失败把原因返回界面（并写审计）。

### 4.23 方案库只做"发现+摘要"，绑定用路径而不是复制内容

- `FlowCatalog` 扫描目录并复用 `FlowLoader/FlowValidator` 判断可用性，避免出现"能选但跑不了"的方案；
- 工单只保存 `flow_path`，不复制方案内容：改方案文件即生效，也不会让数据库膨胀；
- 自动加载失败不静默：界面显示具体错误，仍允许手工加载其它方案；
- 额外的"方案产品 == 工单产品"门禁，解决换线时最常见的跑错程序问题。

### 4.24 用户停用而不是删除

- 删除账号会让历史审计/运行记录的操作员变成"孤儿"，因此只提供启用/停用；
- 登录时校验 `enabled`，停用账号即使口令正确也拒绝，并写审计；
- 保护规则放在界面层（不能停用自己、至少一个启用管理员），因为这是操作约束而非数据约束；
- 口令仍只存盐 + 摘要，重置口令等价于换盐换摘要。

### 4.25 追溯检索用 instr 而不是 LIKE

- `LIKE` 会把用户输入的 `%`/`_` 当通配符，导致"输入 % 返回全部"这种反直觉行为；
- 改用 `instr(lower(col), lower(:key)) > 0`，关键字按字面匹配；
- 空关键字/空判定必须绑定成非 NULL 的空串（SQLite 中 `NULL = ''` 不成立）；
- 检索与批量导出解耦：检索只改列表，导出仍以选中运行为准。

### 4.26 合格证标签用 QPainter 直接绘制，不引入模板系统

- 标签内容固定（公司/SN/产品/工单/时间/检验员/PASS），用比例排版即可适配不同尺寸；
- 尺寸来自 `station.json` 的 `label.widthMm/heightMm`，通过 `QPageSize` 自定义毫米页面；
- PASS 落库后自动生成到标签目录（默认 AppData/labels），文件名带 SN 与时间戳，避免覆盖；
- 失败不阻断测试结论：只写审计并在摘要区提示，不影响已保存的运行记录。

### 4.27 SPC 联动复用 Andon 事件，而不是新增停线机制

- 判定发生在落库后：对流程里有实测值 + 规格限的 measure 步骤，取最近 100 个样本算 Cpk；
- 与"连续 FAIL/FPY"共用 `andon_event`、看板横幅与管理员解除流程，现场只需要学一套；
- 阈值与最小样本数配置在 `spc` 段，避免刚开工样本太少就误停线；
- 停线原因带上测试项名、Cpk、阈值与样本数，便于工艺直接定位。

### 4.28 波形交互只改显示窗口，不改采集与缓冲

- 缩放只调整 `WaveformView::windowSeconds_`（钳制 1~10 秒，滚轮 1.25 倍步进），不重建环、不重采样；
- 改窗宽前先 `flushBucket()`，避免把一个像素桶的数据拆到两个窗里造成跳变；
- 游标把鼠标 x 映射为时间后二分查找最近点，只显示前 8 通道读数，避免高通道数时信息过载；
- 双游标 A/B 只在"像素坐标 → 时间"这一层做换算，不保存采样点副本：左键定 A、右键定 B，
  ΔT 与逐通道 ΔV 在绘制时实时算；双击清除，切换设备时随 `clearData()` 一并复位；
- 限值叠加直接复用通道配置的 `high/low`（与报警同源），不新建"波形限值"配置体系。

### 4.29 原始波形在 UI 定时器里"旁路"累积，而不是新增采集线程

- `MainWindow::onTick` 消费分块时按需追加到捕获缓冲，与绘制的消费循环共用一次读取；
- 捕获上限 20 秒（`sampleRateHz × 20` 点），到上限自动停止并进入"待保存"，防止无界内存；
- 导出 CSV 带 UTF-8 BOM，首列 `time_s`，其余列 `通道名(单位)`，与波形通道顺序一致；
- 切换设备或断线调用 `resetCapture()`，避免把两台设备的数据拼在一起。

### 4.30 自动重连用"令牌 + 单次定时器"，手动断开优先

- 每次显式连接 `++token` 并复位尝试次数；定时器回调先校验令牌，过期回调直接丢弃；
- 退避 `min(16, 1 << min(attempt,4))` 秒（1/2/4/8/16，封顶 16 秒），`opened` 后清零；
- 手动断开置 `manualDisconnect_` 并 `++token`，到期回调直接返回，不重连；
- `reopen()` 按 `mode_` 用上次参数分派到四种协议的连接函数，新增协议只需加一个分支。

### 4.31 校准在"入环前"统一应用，点检复用采样窗口

- `applyCalibration` 在 `pushChunk` 之前按 `gain/offset` 修正，波形、摘要、测试看到的是同一份修正值；
- 未配置校准的通道直接跳过（默认 `gain=1/offset=0`），旧配置零改动；
- 点检复用 `ITestDevice::sampleWindow(ch, 500)` 取均值与 `checkValue ± checkTolerance` 比较，不新增采集通路；
- 点检结果写审计，用于回答"这台设备当天是否点检过"。

### 4.32 日报用 SQL 聚合，备份/压缩用 SQLite 原生命令

- `productionReport` 一条 SQL 按 `date(started_at/1000,'unixepoch','localtime') + shift` 分组，
  统计运行数、PASS/FAIL、去重产量与首次 PASS 数，界面只负责写 CSV；
- 备份用 `VACUUM INTO ?` 生成一致性快照（无需停服、不阻塞写入）；
- 压缩用 `VACUUM` 回收空间；两者都在 UI 线程执行但只操作单文件，耗时可控；
- SN 白名单独立小表 `(work_order, sn)` 主键去重，导入用 `INSERT OR IGNORE`，不做全量替换以免误删。

## 5. 依赖与构建

| 依赖 | 用途 | 缺失时 |
|---|---|---|
| Qt 6（Core/Network/SerialPort/Widgets/Sql/Test/Qml） | 全部功能（Qml 提供 QJSEngine，Gui 提供 QPdfWriter） | 必须 |
| open62541 v1.4.6 | OPC UA 客户端/模拟器服务端 | 自动关闭 OPC UA，其余功能正常 |
| CMake ≥ 3.21 + Ninja | 构建 | 必须 |
| SQLite | 通过 Qt SQL 插件 | 无历史功能 |

open62541 采用 amalgamation（单文件）模式，并开启 `UA_ENABLE_SUBSCRIPTIONS`（OPC UA 订阅依赖）；
v1.4.6 在 amalgamation 模式下**固定生成动态库**，因此 `deploy.bat` 会把 `libopen62541.dll` 一并复制到 dist。
