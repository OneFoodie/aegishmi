# 05 设备协议接入说明

> 项目：AegisHMI　版本：v0.1.0
> 面向"想接入新设备/新协议"的开发者：这里给出五种接入方式的报文、映射、代码位置与排查方法。

---

## 1. 总览

| 协议 | 传输 | 组帧 | 周期 | 读 | 写 | 采样率 |
|---|---|---|---|---|---|---|
| 自定义帧协议 | TCP | `AA 55 + len + seq + type + payload + CRC16` | 设备主动推送（10 ms/批） | DATA 帧 | COMMAND 帧 | 10 kHz |
| Modbus TCP | TCP | MBAP(7B) + PDU | 主机轮询 20 ms | FC03/FC04 | FC06 | 50 Hz |
| Modbus RTU | 串口 | 站号(1B) + PDU + CRC16(低字节在前) | 主机轮询 50 ms | FC04 | FC06 | 20 Hz |
| OPC UA | TCP | UA 二进制（open62541） | 订阅发布 100 ms | 订阅通知 | 写节点 0/1 | 10 Hz |
| SCPI 仪器 | TCP(5025) | ASCII 命令行，`\n` 结束 | 主机轮询（默认 100 ms） | `MEAS:VOLT:DC?` 等查询 | `SOUR:VOLT/CURR`、`*RST` | 10 Hz |

## 2. 自定义帧协议

### 2.1 报文

```
AA 55 | len(LE u16) | seq(LE u16) | type(u8) | payload(len) | crc16(LE u16)
```

- CRC16/MODBUS，覆盖 `len...payload`（不含帧头与 CRC 本身）；
- `len` 最大 65536（中度规模：32 通道 × 100 点约 6.4 KB/帧）。

### 2.2 数据帧（type=0x01）

```
payload = u32 timestampMs(LE) + N × int16 交叠采样
```

N 通道时采样顺序：`ch0 ch1 ... chN-1 ch0 ch1 ...`（N 由 `configs/devices/active.json` 决定）。
模拟器每 10 ms 发 100 个采样点（600 个 int16，1213 字节含头尾）。
上位机按 `timestamp + i / sampleRate` 还原每个点的时间。

### 2.3 命令帧（type=0x20）与应答帧（type=0x81）

```
Command: cmdId(u8) | channel(u8) | value(i16 LE) | 0
Ack    : cmdId(u8) | status(u8)  | measured(i16 LE) | 0
```

| cmdId | 命令 | value 含义 | status |
|---|---|---|---|
| 0x01 | SET_VOUT | 输出电压 mV（0~15000） | 0 成功 / 1 越界 |
| 0x02 | SET_IOUT | 输出电流 mA（0~5000） | 0 成功 / 1 越界 |
| 0x03 | READ_MEASURE | channel 指定通道 | 0 成功，measured 为值 |
| 0x04 | RESET | 忽略 | 0 成功 |

上位机 `DeviceService::sendCommand` 会阻塞等待同一 `seq` 的 Ack，默认超时可配置。

### 2.4 接入新设备的检查清单

1. 通道数、采样率与 `configs/devices/active.json` 一致（两端读同一份配置）；
2. 时间戳单调递增，单位毫秒；
3. 命令应答必须回显请求的 `seq`（上位机据此匹配，避免历史应答干扰）；
4. 断线重连后序号可以从任意值开始（上位机不依赖连续性判断丢帧，只做统计）。

## 3. Modbus TCP

### 3.1 报文

```
MBAP: transactionId(u16 BE) | protocolId(u16 BE=0) | length(u16 BE) | unitId(u8)
PDU : function(u8) | data...
```

- `length` = 后续字节数（unitId + PDU）；
- 事务号：轮询使用 1~0x7FFF，写寄存器使用 `0x8000 | 序号`，两者互不干扰。

### 3.2 功能码

| 功能码 | 用途 | 请求 | 正常响应 |
|---|---|---|---|
| 0x03 | 读保持寄存器 | 起始地址 u16 + 数量 u16 | 字节数 u8 + N×u16 |
| 0x04 | 读输入寄存器 | 同上 | 同上 |
| 0x06 | 写单个寄存器 | 地址 u16 + 值 u16 | 原样回显 |
| 异常 | 功能码 \| 0x80 | — | 异常码 u8 |

异常码：0x01 非法功能、0x02 非法地址、0x03 非法数据值、0x04 从站故障。

### 3.3 寄存器映射（模拟器约定）

| 地址 | 内容 | 单位 | 读写 |
|---|---|---|---|
| 0 | 输出电压 | mV | R/W（FC06 写） |
| 1 | 输出电流 | mA | R/W（FC06 写） |
| 2 | 温度 | 0.1 ℃（250 = 25.0 ℃） | R |
| 3~5 | 预留 | — | R |

轮询：地址 0 起读 6 个寄存器，周期 20 ms（50 Hz），单次请求超时后跳过本轮。

### 3.4 接入真实设备

- 修改 `ModbusTcpClient` 的起始地址/数量（或在 `DeviceService` 里做成配置项）；
- 确认字节序：Modbus 为大端；32 位量需按设备手册决定高低字顺序；
- 站号（unitId）从站一般为 1，网关后面可能是 1~247。

## 4. Modbus RTU

### 4.1 报文

```
[站号 u8] [功能码 u8] [数据...] [CRC16 低字节] [CRC16 高字节]
```

- CRC16/MODBUS，**低字节先发**（与很多协议相反，容易踩坑）；
- 帧间至少 3.5 字符静默（本实现按固定 50 ms 周期轮询，天然满足）；
- 本工程用 FC04 轮询、FC06 写寄存器，与 TCP 版共用 `modbus::Request/Response`。

### 4.2 示例：读 6 个输入寄存器（站号 1，地址 0）

```
请求：01 04 00 00 00 06 70 08
响应：01 04 0C 13 88 03 E8 00 FA 00 00 00 00 00 00 D7 EA
      其中 0x1388=5000(mV)、0x03E8=1000(mA)、0x00FA=250(温度)
```

### 4.3 运行期验证

本机没有串口设备，**RTU 运行期尚未实机验证**。验证方法：

1. 安装虚拟串口对（com0com），一端给上位机（`COM3`），另一端给支持 RTU 的模拟器/从站；
2. 串口参数：115200-8-N-1（界面可选 9600~115200）；
3. 观察日志与统计：若持续超时，优先检查站号、波特率、A/B 线序。

## 5. OPC UA

### 5.1 端点与节点

| 项 | 值 |
|---|---|
| 端点 | `opc.tcp://<host>:4840` |
| 命名空间 | 1 |
| 节点 | `ns=1;s=Channel0` ~ `ns=1;s=Channel5` |
| 数据类型 | Double（读兼容 Float/Int32/UInt16/Int16；写仅 Double） |
| 权限 | 节点 0/1 读写（设定值），节点 2~5 只读 |
| 读取方式 | Subscription + MonitoredItem，发布周期 100 ms（不再逐点轮询） |

### 5.2 客户端行为

`OpcUaClient::open(endpoint, nodeIds)`：

1. `UA_Client_new` + `UA_ClientConfig_setDefault`（SecurityPolicyNone、匿名）；
2. 同步 `UA_Client_connect`；失败发 `failed(reason)` 并释放；
3. `UA_Client_Subscriptions_create` 建 1 个订阅（发布周期 100 ms）；
4. 每个节点 `UA_Client_MonitoredItems_createDataChange`（采样周期 100 ms，队列 4）；
   某个节点创建失败只记录错误，不阻断其它节点（该通道读数为 0）；
5. 10 ms 定时器调用 `UA_Client_run_iterate` 处理 Publish 响应；
   每 100 ms 把最新缓存以 `QVector<double>` 通过 `valuesUpdated` 交给 `DeviceService`。

写设定值：`writeValue(transaction, index, value)` 调用 `UA_Client_writeValueAttribute`
把 Double 写入节点；结果通过 `writeCompleted(transaction, ok, status)` 回传，
`DeviceService` 在 OPC UA 模式下把 `SET_VOUT/SET_IOUT` 映射为写节点 0/1。

无 GUI 验证工具：

```bat
build-mingw\bin\aegis_opcua_probe.exe opc.tcp://127.0.0.1:4840
build-mingw\bin\aegis_opcua_probe.exe opc.tcp://127.0.0.1:4840 0 7000
```

### 5.3 模拟器实现

`simulator/main.cpp` 在 `startOpcUa()` 中：

- `UA_Server_new` + `UA_ServerConfig_setMinimal`（默认 4840）；
- 在 Objects 下创建 N 个 `double` 变量节点（N = 配置通道数），节点 0/1 的 `accessLevel` 含 WRITE；
- 10 ms 定时器调用 `UA_Server_run_iterate`；
- 每个数据周期读回节点 0/1，若与"上次写出的值"不同，说明客户端写了新设定值，
  用它更新 `voutMv_/ioutMa_`；随后再把当前设定值写回节点（只连 OPC UA 时也持续刷新）。

### 5.4 构建注意事项

| 问题 | 处理 |
|---|---|
| 源码获取 | `scripts/fetch_open62541.ps1`（v1.4.6） |
| 需要单文件头 | `UA_ENABLE_AMALGAMATION=ON` |
| 订阅支持 | `UA_ENABLE_SUBSCRIPTIONS=ON`（本工程默认开启） |
| MinGW 下 SJLJ 展开符号缺失 | 关闭 PubSub 及其信息模型（`UA_ENABLE_PUBSUB*`） |
| MinGW 13 无 `-lssp` | `third_party/lib/libssp.a` 空归档垫片 |
| amalgamation 固定生成 DLL | `deploy.bat` 复制 `libopen62541.dll` |

### 5.5 生产化建议

- 启用 `SecurityPolicyBasic256Sha256` + 证书，关闭匿名登录；
- 订阅参数可按设备能力调整：采样/发布周期、队列长度、`requestedMaxKeepAliveCount`；
- 写节点时注意数据类型与权限：本工程按 Double 写入，其它类型需在 `writeValue` 中转换；
- 需要断线重连时，在 `DeviceService` 层监听 `failed` 并做退避重连（当前未实现）。

## 6. SCPI 仪器（SCPI-RAW over TCP）

面向台式电源/万用表/电子负载等支持 LAN 接口的仪器，走最常见的 **SCPI-RAW over TCP（端口 5025）**，
不依赖 NI-VISA：一条 TCP 连接上按行收发 ASCII 命令（以 `\n` 结尾）。

### 6.1 连接与查询

| 项 | 值 |
|---|---|
| 端点 | `tcp://<host>:5025` |
| 帧格式 | ASCII 文本，一行一条命令，`\n` 结束 |
| 采集方式 | 周期查询（默认 `MEAS:VOLT:DC?`，间隔 `scpiPollMs`） |
| 并发 | 同一时刻只允许一个在途请求，其余排队（避免应答错配） |
| 超时 | 每请求默认 2000 ms；超时按失败返回，不阻塞后续请求 |

`ScpiClient` 只做三件事：`open/close`、`setPolling(命令, 间隔)`、`writeCommand/query`。
查询结果通过 `queryCompleted(transaction, ok, text)` 返回，轮询结果解析首个字段为 double，
经 `measurement(value)` 交给 `DeviceService`。

### 6.2 与统一命令的映射

| 统一命令 | SCPI 报文 | 说明 |
|---|---|---|
| `SET_VOUT` | `SOUR:VOLT <mV/1000>` | 3 位小数，单位 V |
| `SET_IOUT` | `SOUR:CURR <mA/1000>` | 3 位小数，单位 A |
| `RESET` | `*RST` | 仪器复位 |
| `READ_MEASURE` | 复用周期查询命令 | 返回最近一次轮询值 |

轮询值 × `scpiScale` 后写入 CH0（`scpiScale = 1000` 表示 V→mV，与内部毫伏口径一致）。

### 6.3 设备清单配置

```json
{ "id": "dmm1", "name": "台式万用表", "protocol": "scpi",
  "host": "192.168.1.50", "port": 5025,
  "scpiQuery": "MEAS:VOLT:DC?", "scpiPollMs": 100, "scpiScale": 1000 }
```

`scpiPollMs` 会被限制在 50~5000 ms；`scpiScale` 非法（0/负数/非数字）时按 1.0 处理。

### 6.4 模拟器与测试

- `aegis_sim.exe --scpi-port 5025`（默认开启）支持 `*IDN?`、`MEAS:VOLT:DC?`、`MEAS:CURR:DC?`、
  `SOUR:VOLT x`、`SOUR:CURR x`、`*RST`、`*OPC?`；
- `tst_scpi` 用进程内 `QTcpServer` 假仪器覆盖：查询应答、只写确认、无响应超时、轮询产出测量值。

## 7. 新增一种协议的最小改动

1. `infra/` 增加客户端类（QObject，`open/close` + 数据信号），必要时 `moveToThread`；
2. `ConnectionMode` 增加枚举值；
3. `DeviceService` 增加 `connectXxx`、信号槽、`sampleRateHz()` 分支、`sendCommand` 映射（如需写）；
4. 主界面协议下拉增加一项，并在 `toggleConnection` 分发；
5. 模拟器增加对应服务端（便于无硬件演示）；
6. 补一个测试目标（编解码 + 进程内假服务端）。

## 8. 常见问题排查

| 现象 | 可能原因 | 排查 |
|---|---|---|
| 连接成功但无波形 | 设备未推数据 / 通道数不一致 | 看统计"帧数/字节数"是否增长 |
| 波形跳变或乱序 | 时间戳非毫秒 / 序号回绕处理错误 | 抓包核对 DATA 负载前 4 字节 |
| CRC 错误计数增长 | 波特率不匹配 / 干扰 / 帧头误判 | 降低波特率，检查屏蔽与接地 |
| Modbus 一直超时 | 站号错误、寄存器地址越界、字节序 | 用 Modbus Poll 等工具先验证从站 |
| OPC UA 连接失败 | 端点 URL 错误、端口占用、策略不支持 | 看日志里的 `UA_StatusCode_name` |
| 启动报 0xC0000135 | 缺少 `libopen62541.dll` | 重新执行 `deploy.bat` |
| 界面卡顿 | 绘制路径退化（非 cosmetic 画笔） | 确认画笔 `width=1` + `cosmetic` |

## 9. 通道配置与报警阈值

`configs/devices/active.json` 的每个通道除 `name/unit/description` 外，还可选配报警阈值：

```json
{
  "name": "CH0",
  "unit": "mV",
  "description": "输出电压",
  "high": 6000,
  "low": 4000,
  "deadband": 50
}
```

| 字段 | 含义 | 缺省 |
|---|---|---|
| high | 高报警阈值（avg 超过即报警） | 不报警 |
| low | 低报警阈值（avg 低于即报警） | 不报警 |
| deadband | 回差：高报警需回落到 `high-deadband`、低报警需回升到 `low+deadband` 才恢复 | 0 |

注意：

- 模拟器与上位机必须使用同一份通道配置（通道数、名称），阈值只影响上位机报警判定，不参与协议；
- 阈值单位与该通道 `unit` 一致；数据本身是 int16 原始值，不做量纲换算；
- 未配置阈值的通道既不产生报警，也不会出现在 `alarm_event` 表中。
