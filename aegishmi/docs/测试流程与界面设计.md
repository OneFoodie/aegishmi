# 测试流程配置格式与界面设计

> 对应里程碑 M3（测试流程引擎）。本文只做设计，不含实现代码。
> 目标：把当前"波形监视器"升级为"自动测试上位机"，可配置测试方案、自动执行、自动判定、出报告。

---

## 1. 设计目标与边界

**目标**
- 测试方案用配置文件描述，换产品不改代码
- 引擎按步骤下发命令、等待应答、采集数据、判定上下限
- 全过程可观测：当前步骤、实测值、判定结果、耗时
- 执行结果可保存、可导出，作为测试报告

**边界（先不做）**
- 不做多工位并行执行（单流程串行）
- 不做图形化流程编辑器（先手写/复制 JSON）
- 不做脚本语言（用声明式 JSON，够用且好校验）
- 不做用户权限体系

---

## 2. 流程配置格式（JSON）

### 2.1 文件位置与命名

```
aegishmi/configs/flows/<产品>_<方案>.json
例：configs/flows/power_module_basic.json
```

### 2.2 完整示例

```json
{
  "schemaVersion": 1,
  "id": "power_module_basic",
  "name": "电源模块出厂测试",
  "description": "5V 输出电源模块的基础功能测试",
  "product": "PM-5V-10A",
  "defaultTimeoutMs": 1000,
  "onFailure": "abort",
  "variables": {
    "voutNominalMv": 5000,
    "ioutNominalMa": 1000
  },
  "steps": [
    {
      "id": "s1",
      "name": "设置输出电压 5V",
      "action": "command",
      "params": { "cmd": "SET_VOUT", "valueMv": "${voutNominalMv}" },
      "timeoutMs": 500,
      "expect": { "ackStatus": 0 }
    },
    {
      "id": "s2",
      "name": "设置限流 1A",
      "action": "command",
      "params": { "cmd": "SET_IOUT", "valueMv": "${ioutNominalMa}" },
      "timeoutMs": 500,
      "expect": { "ackStatus": 0 }
    },
    {
      "id": "s3",
      "name": "等待输出稳定",
      "action": "delay",
      "params": { "ms": 300 }
    },
    {
      "id": "s4",
      "name": "测量输出电压",
      "action": "measure",
      "params": { "channel": 0, "windowMs": 200 },
      "expect": { "metric": "avg", "min": 4750, "max": 5250, "unit": "mV" },
      "timeoutMs": 1000
    },
    {
      "id": "s5",
      "name": "测量输出电流",
      "action": "measure",
      "params": { "channel": 1, "windowMs": 200 },
      "expect": { "metric": "avg", "min": 900, "max": 1100, "unit": "mA" }
    },
    {
      "id": "s6",
      "name": "纹波峰峰值检查",
      "action": "measure",
      "params": { "channel": 0, "windowMs": 500 },
      "expect": { "metric": "peakToPeak", "max": 50, "unit": "mV" },
      "onFail": "continue"
    }
  ]
}
```

### 2.3 字段说明

**顶层**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| schemaVersion | int | 是 | 配置格式版本，当前 1；加载时校验，便于将来升级 |
| id | string | 是 | 方案唯一标识，同时作为落库主键的一部分 |
| name | string | 是 | 显示名称 |
| description | string | 否 | 说明 |
| product | string | 否 | 适用产品型号 |
| defaultTimeoutMs | int | 否 | 单步默认超时，默认 1000 |
| onFailure | string | 否 | `abort`（默认，失败即停）/ `continue`（继续执行后续步骤） |
| variables | object | 否 | 变量表，供步骤里用 `${name}` 引用 |
| steps | array | 是 | 步骤列表，至少 1 个 |

**步骤（steps[]）**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | string | 是 | 步骤唯一标识（流程内不可重复） |
| name | string | 是 | 显示名称 |
| action | string | 是 | `command` / `delay` / `measure` / `assert` |
| params | object | 视 action | 动作参数 |
| expect | object | 视 action | 判定条件；没有则不判定，只记录 |
| timeoutMs | int | 否 | 覆盖默认超时 |
| retries | int | 否 | 失败重试次数，默认 0 |
| onFail | string | 否 | 覆盖顶层失败策略 |

**各 action 的参数**

| action | params | expect | 语义 |
|---|---|---|---|
| `command` | `cmd`(string)、`channel`(int,可选)、`valueMv`/`value`(int,可选) | `ackStatus`(int) | 下发命令帧，等待 Ack，比对状态码 |
| `delay` | `ms`(int) | 无 | 纯等待，用于让设备输出稳定 |
| `measure` | `channel`(int)、`windowMs`(int) | `metric`、`min`、`max`、`unit` | 在窗口内采集该通道，计算统计量后与上下限比较 |
| `assert` | `expression`（暂不开放，保留） | — | 预留：对已有结果做组合判断 |

**metric 统计量**：`avg`（平均）、`min`、`max`、`rms`（有效值）、`peakToPeak`（峰峰值）。

### 2.4 变量替换

步骤里任意字符串值支持 `${varName}`，加载时用 `variables` 展开：

```json
"valueMv": "${voutNominalMv}"
```

未定义的变量视为配置错误，加载阶段直接报错，不允许带病运行。

### 2.5 校验规则（加载时执行，错误全部列出）

1. `schemaVersion` 必须为 1
2. `id`、`name`、`steps` 非空；步骤 `id` 不重复
3. `action` 必须是已知类型
4. `measure.channel` 在 `[0, 通道数)` 范围内；`windowMs` 在 `[10, 10000]`
5. `expect.min < expect.max`；数值字段必须是数字
6. `timeoutMs` 在 `[10, 60000]`
7. 变量引用必须已定义
8. 至少一个 `measure` 步骤（否则"测试"没有意义）

校验失败时界面显示"配置错误 + 行号/字段路径"，禁止启动。

## 3. 执行语义

### 3.1 状态机

```
Idle ──开始──▶ Running ──全部通过──▶ Passed
                  │  ├──任一步失败(abort)──▶ Failed
                  │  ├──用户点停止/断线────▶ Aborted
                  └──继续(continue)────────▶ 继续下一步
```

### 3.2 单步执行流程

1. 记录开始时间，状态置 `Running`，界面高亮该行
2. 按 action 执行：
   - `command`：编码命令帧 → 发送 → 等待 Ack（超时则失败）
   - `delay`：等待指定时长（期间不阻塞 UI，用定时器/条件变量）
   - `measure`：从当前时刻起，采集 `windowMs` 内该通道的所有采样点 → 计算 metric
3. 有 `expect` 时判定：`min ≤ 实测 ≤ max` → Pass，否则 Fail
4. 记录：实测值、判定、耗时、失败原因（超时/断线/越界/应答错误）
5. 失败且策略为 abort → 整体 Aborted；`retries > 0` 时先重试

### 3.3 测量窗口的实现要点

- 引擎不能直接读环形缓冲（会与 UI 抢数据）
- `DeviceService` 增加"按通道取样窗口"能力：订阅后把窗口内的采样点复制一份给引擎
- 采样点不足窗口长度的 80%（例如设备掉线）→ 判定为"数据不足"失败

### 3.4 线程模型

- `TestEngine` 运行在独立 `QThread`，避免阻塞 UI
- 与 UI 通过信号通信：`stepStarted(index)`、`stepFinished(index, result)`、`runFinished(verdict)`
- 与设备通过接口通信（见 3.5），便于用 Mock 做单元测试

### 3.5 设备命令协议扩展（需要同步改模拟器）

现有协议只有 DATA / Ping / Ack。为支持测试流程，增加：

```
type = 0x20 (Command)
payload = cmdId(u8) | channel(u8) | value(i16 LE) | reserved(u8)

type = 0x81 (Ack)
payload = cmdId(u8) | status(u8) | measured(i16 LE)
```

命令字：

| cmdId | 名称 | 参数 | 说明 |
|---|---|---|---|
| 0x01 | SET_VOUT | value | 设置输出电压（mV） |
| 0x02 | SET_IOUT | value | 设置限流（mA） |
| 0x03 | READ_MEASURE | channel | 读取瞬时值 |
| 0x04 | RESET | — | 复位设备 |

`status`：0 = 成功，非 0 = 错误码（1 超范围、2 忙、3 不支持）。

模拟器相应实现：维护"设定值"，让 CH0 幅值随 SET_VOUT 变化，这样"设置 → 测量"的测试流程才有真实意义。

│ [监控] [自动测试] [历史]                                       │

左侧的设备连接面板、日志面板移到"监控"页；"自动测试"页独立布局，避免拥挤。

### 4.3 控件与状态

| 区域 | 控件 | 行为 |
|---|---|---|
| 左栏 | "加载方案"按钮 | 文件对话框，选 JSON；加载后立即校验并显示结果 |
| 左栏 | 方案信息 | 名称/产品/步骤数/校验状态（绿色"通过"或红色错误列表） |
| 左栏 | 最近方案下拉 | 记录最近 5 个路径（QSettings 持久化） |
| 顶部 | 开始测试 | 未连接/校验失败时禁用，悬停提示原因 |
| 顶部 | 停止 | 执行中可用，点击后当前步骤标"中止" |
| 顶部 | 进度条 + 文本 | `已完成/总数`，每步结束刷新 |
| 中间 | 步骤表格 | 5 列：序号、步骤名、状态、实测值、判定、耗时 |
| 底部 | 结果摘要 | 总判定、开始时间、总耗时、SN 输入框 |
| 底部 | 导出 CSV | 有结果后可用 |

### 4.4 颜色与状态

| 状态 | 颜色 | 说明 |
|---|---|---|
| 等待 | 灰 | 尚未执行 |
| 执行中 | 蓝 + 加粗 | 当前步骤，行背景浅蓝 |
| 通过 | 绿 | 实测值在范围内 |
| 失败 | 红 | 越界/超时/应答错误，实测值标红 |
| 跳过 | 黄 | 前序失败且策略为 abort 的后续步骤 |
| 中止 | 橙 | 用户停止或断线 |

失败行支持悬停查看原因（超时 1000ms / 应答 status=1 / 实测 5300 超出 [4750,5250]）。

### 4.5 交互流程

1. 连接设备（沿用现有自动连接）
2. 切到"自动测试"页 → 点"加载方案…" → 选 JSON
3. 界面显示校验结果；通过则"开始测试"可用
4. 点开始 → 表格逐行高亮执行 → 进度条推进
5. 结束：弹窗/摘要区显示 PASS/FAIL，失败步骤红色高亮
6. 可选：填 SN → 保存记录 → 导出 CSV
7. 异常：执行中断线 → 立即中止，后续步骤标"跳过"，日志记录原因

### 4.6 与监测页的联动

- 测试执行期间，"监控"页波形照常刷新（数据源不变）
- 测试步骤产生的"测量窗口"在波形上叠加一条浅色竖线标记（可选，二期）

## 5. 数据模型（为 SQLite 做准备）

```sql
CREATE TABLE test_run (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    flow_id      TEXT NOT NULL,
    flow_name    TEXT NOT NULL,
    product      TEXT,
    sn           TEXT,
    verdict      TEXT NOT NULL,      -- PASS / FAIL / ABORTED
    started_at   INTEGER NOT NULL,   -- Unix 毫秒
    finished_at  INTEGER,
    operator     TEXT
);

CREATE TABLE test_step (
    run_id       INTEGER NOT NULL,
    step_index   INTEGER NOT NULL,
    step_id      TEXT NOT NULL,
    name         TEXT NOT NULL,
    action       TEXT NOT NULL,
    status       TEXT NOT NULL,      -- PASS / FAIL / SKIPPED / ABORTED
    measured     REAL,
    metric       TEXT,
    lower_limit  REAL,
    upper_limit  REAL,
    unit         TEXT,
    elapsed_ms   INTEGER,
    message      TEXT,
    PRIMARY KEY (run_id, step_index),
    FOREIGN KEY (run_id) REFERENCES test_run(id)
);
```

CSV 导出：一行一个步骤，列 = 方案、SN、步骤、状态、实测、上下限、单位、耗时、时间。

## 6. 类设计

```
src/test/
├─ flow_types.h          // TestFlow / TestStep / StepAction / ExpectSpec
├─ flow_loader.h/.cpp    // JSON -> TestFlow，含变量替换
├─ flow_validator.h/.cpp // 校验规则，返回错误列表
├─ test_engine.h/.cpp    // QObject，状态机 + 执行
├─ test_result.h         // StepResult / RunResult
└─ device_command.h      // 命令字与编解码（与模拟器共享）
```

关键接口：

```cpp
// 引擎依赖抽象，便于单测用 Mock（不需要真实设备）
class ITestDevice {
public:
    virtual ~ITestDevice() = default;
    virtual bool sendCommand(DeviceCommand cmd, int channel, int value, int timeoutMs,
                             quint8& status) = 0;
    virtual std::vector<std::int16_t> sampleWindow(int channel, int windowMs) = 0;
};

class TestEngine : public QObject {
    Q_OBJECT
public:
    TestEngine(ITestDevice* device, QObject* parent = nullptr);
    void start(const TestFlow& flow);
    void stop();
signals:
    void stepStarted(int index);
    void stepFinished(int index, const StepResult& result);
    void runFinished(const RunResult& result);
};
```

`DeviceService` 实现 `ITestDevice` 的生产版本；单元测试用 `MockDevice` 直接返回设定值，验证判定逻辑、超时、重试、abort/continue。
