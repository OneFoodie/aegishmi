> 项目：AegisHMI　版本：v0.1.0

## 1. 自定义帧协议

### 1.1 字节布局

```
偏移  0      2        4        6      7           7+len      9+len
     AA 55 | len(LE) | seq(LE) | type | payload... | crc16(LE)
```

- 固定开销 9 字节；总长 = 9 + len；
- `len` 上限 `kMaxPayload = 4096`，超过视为帧头误判；
- CRC16/MODBUS（多项式 0xA001，初值 0xFFFF），覆盖 `len + seq + type + payload`。

### 1.2 帧类型

| type | 名称 | 负载 |
|---|---|---|
| 0x01 | Data | `u32 时间戳(ms, LE)` + N×`int16` 交叠采样 |
| 0x02 | Info | 文本（预留） |
| 0x10 | Ping | 空 |
| 0x11 | SetRate | 预留 |
| 0x20 | Command | `cmdId u8 | channel u8 | value i16 LE | 保留 u8` |
| 0x81 | Ack | `cmdId u8 | status u8 | measured i16 LE | 保留 u8` |

### 1.3 状态机（FrameCodec::feed）

```
[累积字节] → 找 AA 55（不匹配则 pos+1）
          → 头部不足 9 字节：break，等下一次 feed
          → len > 4096：pos+1 重新对齐
          → 整帧未到齐：break（半包）
          → CRC 错误：crcErrors++，pos+1 重新对齐
          → 成功：回调 handler(frame)，pos += 整帧长度
[循环结束] → 丢弃 [0, pos) 已处理字节
```

设计要点：

- **重同步只前进 1 字节**：CRC 失败可能是帧头巧合，直接丢弃整帧会连带丢掉后面的好帧；
- **回调里禁止耗时操作**：handler 在收包路径上执行，重活应转交队列/线程；
- 粘包（一次读到多帧）由循环自然处理，分包（半帧）由 `break` + 保留缓冲区处理。

## 2. 环形缓冲与通道配置

### 2.1 设备通道配置（core::DeviceConfig）

```json
{
  "schemaVersion": 1,
  "channelCount": 32,
  "sampleRateHz": 10000,
  "channels": [
    { "name": "CH0", "unit": "mV", "high": 6000, "low": 4000, "deadband": 50,
      "gain": 1.0, "offset": 0.0, "check": 5000, "checkTolerance": 50 },
    { "name": "CH1", "unit": "mA" }
  ]
}
```

- 读取顺序：`AEGIS_DEVICE_CONFIG` → exe 目录/configs/devices/active.json →
  开发目录/configs/devices/active.json → 默认 6 通道；
- `channelCount` 钳制到 1~64，`sampleRateHz` 钳制到 100~1e6，channels 不足自动补 `CH%1`；
- `gain`/`offset` 缺省为 1.0/0.0；`check` 存在时启用该通道的日常点检，`checkTolerance` 缺省 0；
- 协议层用它校验 `samples.size() % channelCount == 0`，不匹配的帧记录日志并丢弃。

### 2.2 分块环形缓冲（core::ChunkRingBuffer）

```cpp
struct ChunkView {                 // 只在 consume 回调期间有效
    std::uint32_t timestampMs;     // 本块第一个点的时间戳
    float startSec;                // 显示时间
    int pointCount; int channelCount;
    const std::int16_t* samples;   // pointCount × channelCount
};

class ChunkRingBuffer {
    bool push(std::uint32_t ts, float startSec, const std::int16_t* data, int points);
    template <class Fn> void consume(Fn&& fn);  // 逐块回调，返回后槽位可复用
};
```

- 槽位预分配：capacity × (maxPointsPerChunk × channelCount × 2 B)；
  本项目 256 槽 × 512 点 → 32 通道约 8 MB，6 通道约 1.5 MB；
- 生产者写入槽位后 `head_.store(release)`；消费者读取 `head_.load(acquire)`，处理完统一前移 tail；
- 满时 push 返回 false，上层按点数累加 `dropped`；
- 相比"每点一个结构体"：64 通道时内存从约 169 MB/2s 降到约 16 MB/2s。

## 4. DeviceService

### 4.1 状态

```
mode_        : ConnectionMode（原子）
connected_   : 原子 bool
ring_        : ChunkRingBuffer（256 槽 × 512 点 × N 通道）
config_      : 通道数/采样率/通道名
capture*_    : 采样窗口采集（通道号、开关、结果数组、互斥量）
ack*_        : 命令等待（序号、状态、条件变量、互斥量）
stats_       : frames/crcErrors/blocks/dropped/bytes
```

### 4.2 连接与切换

| 入口 | 行为 |
|---|---|
| connectTcp | 关闭 Modbus TCP/RTU/OPC UA → 在通信线程打开 TCP |
| connectModbusTcp | 关闭其它 → 打开 MBAP 会话，启动 20 ms 轮询 |
| connectModbusRtu | 关闭其它 → 打开串口，启动 50 ms 轮询 |
| connectOpcUa | 关闭其它 → 建立 UA 会话并创建订阅（发布周期 100 ms） |
| disconnectDevice | 按当前 mode_ 关闭对应链路 |

所有"打开/关闭"都通过 `QMetaObject::invokeMethod(obj, lambda, Qt::QueuedConnection)` 投递到
通信线程执行；`mode_`/`connected_` 用原子变量，避免跨线程读写竞态。

### 4.3 命令-应答时序（自定义协议）

```
引擎线程                     主线程（onBytes）                通信线程
sendCommand(cmd)
 ├ 登记 ackSeq_/ackReceived_=false
 ├ invokeMethod -> transport->send(frame)
 └ wait_for(ackCv_, timeout)  ←──────┐
                                    │ Ack 帧 → decode → 匹配 seq
                                    │ ackStatus_ = status
                                    └ ackReceived_=true; notify_all
 返回 true/false + status
```

Modbus 模式：`SET_VOUT → FC06 写寄存器 0`，`SET_IOUT → 寄存器 1`；
写事务号使用 `0x8000 | 序号`，与轮询事务号（1~0x7FFF）隔离，避免串号。

OPC UA 模式：`SET_VOUT → 写节点 0`，`SET_IOUT → 写节点 1`（Double，mV/mA）；
写操作在通信线程执行 `UA_Client_writeValueAttribute`，结果通过 `writeCompleted`
回到主线程唤醒 `sendCommand`，与 Modbus 写共用同一套事务号匹配逻辑。

### 4.4 采样窗口（sampleWindow）

1. 校验通道与连接状态；
2. 清空结果，置 `captureActive_ = true`，记录通道；
3. `QThread::msleep(windowMs)`（在引擎线程，不阻塞 UI）；
4. 关闭标志，返回拷贝的结果数组。

Modbus/OPC UA 的 `onModbusRegisters` / `onOpcUaValues` 会构造"1 个采样时刻 × N 通道"的数据块，
直接写入 ChunkRingBuffer；若采集窗口打开，同时把对应通道值加入结果，避免二次遍历。

### 4.5 采样率

| 模式 | sampleRateHz() |
|---|---|
| 自定义协议 | 10000 |
| Modbus TCP | 50（20 ms） |
| Modbus RTU | 20（50 ms） |
| OPC UA | 10（订阅发布 100 ms） |

### 4.6 OPC UA 订阅与写节点

```
open(endpoint, nodeIds)
 ├ UA_Client_new + setDefault
 ├ UA_Client_connect（同步）
 ├ UA_Client_Subscriptions_create（发布周期 100 ms，上下文 = this）
 ├ 对每个节点 UA_Client_MonitoredItems_createDataChange
 │    ├ 采样周期 100 ms，队列 4
 │    ├ 上下文 = 节点下标（intptr 塞进 void*）
 │    └ 失败只记录（该通道读数保持 0），不影响其它节点
 ├ emit opened()，启动 10 ms 定时器
 └ 定时器：UA_Client_run_iterate(client, 0)
         每 10 个 tick（≈100 ms）把 latest_ 通过 valuesUpdated 发出
```

- **为什么用订阅**：轮询时 6 节点 × 10 次/秒 = 60 次 Read/秒，且大多数值未变化；
  订阅只在值变化时推送，Publish 心跳由服务端控制，带宽与设备负载都更低；
- **回调线程**：`onDataChange` 由 `UA_Client_run_iterate` 在通信线程内调用，
  与快照发布同线程，因此缓存 `latest_` 不需要加锁；
- **写节点**：`writeValue(transaction, index, value)` 同步返回后发出 `writeCompleted`；
  成功后同步更新本地缓存（界面立即看到新设定值）；
- **模拟器侧**：节点 0/1 的 `accessLevel` 含 WRITE；每个数据周期读回节点值，
  与"上次写出的值"比较，不同即认为客户端写了新设定值（避免把自定义协议刚设的值覆盖掉）。

## 5. 测试引擎（TestEngine）

### 4.1 输入模型

`TestFlow { id, name, defaultTimeoutMs, onFailure, variables, steps[] }`
`TestStep { id, name, action, params, timeoutMs, retries, onFail, expect }`

action：

| action | 参数 | 结果 |
|---|---|---|
| command | cmd / value / channel | 下发命令并检查 ackStatus |
| delay | ms | 等待，不判定 |
| measure | channel / windowMs | 采集窗口 → 计算指标 → 与上下限比较 |
| script | script（JavaScript 源码） | QJSEngine 执行，异常/false/设备失败即失败 |

metric：`avg` / `min` / `max` / `peakToPeak`。

script 步骤的 JS API（由 `ScriptApi` 注入全局）：

| 函数 | C++ 行为 |
|---|---|
| `setVout(ch, mV)` / `setIout(ch, mA)` | `ITestDevice::sendCommand`，status≠0 记为失败 |
| `measureAvg(ch, windowMs)` | `sampleWindow` → 平均值；样本不足 80% 记为失败 |
| `sleep(ms)` | `ITestClock::sleepMs`（上限 60 s） |
| `log(text)` | 收集到日志，执行后并入步骤说明 |

脚本判定：`evaluate` 返回 Error → 失败；C++ 侧记录到第一条设备错误 → 失败；
显式 `return false` → 失败；否则通过。最后一次 `measureAvg` 的值作为步骤实测值。

### 4.2 执行流程

```
for step in steps:
    attempts = step.retries + 1
    for attempt in 1..attempts:
        result = execute(step)          # command / delay / measure
        if result.pass: break
    if !result.pass:
        policy = step.onFail ?: flow.onFailure
        if policy == "abort": 结束（verdict = Fail）
        else: 继续
verdict = 全部通过 ? Pass : Fail
```

数据不足判定：`expected = windowMs × device.sampleRateHz() / 1000`，
实际样本数 < `expected × 80%` 视为失败（提示"数据不足"），避免低采样率协议误判。

### 4.3 线程与交互

- `TestEngine` 在独立线程执行；每步通过信号 `stepFinished(index, result)` 通知 UI；
- `abort()` 置原子标志，当前步骤结束后退出；
- 引擎只依赖 `ITestDevice`（sendCommand/sampleWindow/sampleRateHz），便于 Mock。

## 6. JSON 流程加载与校验

加载（FlowLoader）：

1. 读文件 → `QJsonDocument::fromJson`，语法错误直接返回行号/偏移；
2. 逐字段取值，缺失必填项、类型不符都记录为"字段路径 + 原因"；
3. 变量表先解析，再对字符串做 `${name}` 替换（未定义变量报错）。

校验（FlowValidator）覆盖：

- `schemaVersion` 必须为 1；
- `id/name/steps` 必填，`steps` 非空且 `id` 不重复；
- `action` 必须是 command/delay/measure/script/assert（assert 未实现，会被拒绝）；
- script 必须提供非空 `script`（≤ 20000 字符），且不能配置 `expect`；
- 至少需要 1 个 measure 或 script 步骤，否则没有任何判定依据；
- command 的 `cmd` 必须是 SET_VOUT/SET_IOUT/READ_MEASURE/RESET；
- measure 的 `channel ∈ [0,63]`（上限 64 通道，实际可用通道由设备配置决定）、`windowMs > 0`、上下限 min ≤ max；
- `onFailure/onFail ∈ {abort, continue}`，`retries ≥ 0`。

错误一次性全部返回，界面以列表展示，定位到 `steps[i].xxx`。

### 6.1 波形摘要表（P3）

```sql
CREATE TABLE sample_summary (
  device_id    TEXT NOT NULL,
  channel      INTEGER NOT NULL,

```

- 写入：`saveSummaryBatch()` 单事务批量插入（`INSERT OR REPLACE`）；
- 查询：`summaryTrend(device, channel, from, to, maxRows)` 按时间升序；
- 清理：`purgeSummariesBefore(epochSec)`，启动时删除 7 天前数据；
- 读取与写入可能并发：`PRAGMA busy_timeout=3000` + WAL。

### 6.2 SummaryWriter（异步写入）

```
主线程                       写线程
summaryReady(device, 1s 摘要)
  └ enqueue() --queued-->  appendRows() → pending_（设备×通道行）
                              └ 每 500ms 或 500 行：flush()
                                   └ saveSummaryBatch()（单事务）
```

- 写线程内创建独立的 `TestRepository`（Qt SQL 连接必须在所属线程使用）；
- **必须无父对象创建** `SummaryWriter`：带父对象时 `moveToThread` 会失败，对象仍留在 UI 线程；
  此时 `stop()` 的 `BlockingQueuedConnection` 会自锁，现象是"关闭窗口后进程不退出、
  模拟器一直显示在线客户端 1"；
- `stop()` 增加同线程判断：若对象与调用者同线程则直接执行收尾，避免再次自锁；
- `stop()` 用阻塞调用刷完剩余数据、释放连接，再退出线程；
- 写失败只丢摘要，不影响采集/显示。

- 旧库迁移：`ensureColumn()` 读取 `PRAGMA table_info`，缺列才 `ALTER TABLE ADD COLUMN`；
- 一码一测：`SELECT COUNT(*) FROM test_run WHERE work_order=? AND sn=?`（索引 `(work_order, sn)`）；
- FPY：对每个 SN 取 `id` 最小的一次运行判定，`首次PASS的SN数 / 去重SN数`；
- 不良 Pareto：`test_step JOIN test_run`，按 `status='FAIL'` 分组计数；
- 上传状态在历史列表里通过 `LEFT JOIN mes_outbox` 带出；
- 首件状态机由 `updateFaiAfterRun()` 推进，`confirmFai()/resetFai()` 由看板按钮调用；
- 待返修/复测通过是派生统计：每个 SN 取 `id` 最大的一次判定，非 PASS 计待返修；
- 治具在测试前读 `fixture_usage` 校验，落库后 `recordFixtureUse()` 递增，复位写 `resetFixture()`。

## 8. 界面

## 10. 质量增强（SPC / SOP / 报告 / 班组 / Andon）

### 10.1 SPC 计算口径

输入：某工单、某 `flow_id + step_id` 的实测值（时间升序）、规格限（可选）。

```
mean  = Σxi / n
sigma = sqrt(Σ(xi - mean)² / (n - 1))          // 样本标准差
Cp    = (USL - LSL) / (6σ)                     // 仅双侧规格
Cpk   = min(USL - mean, mean - LSL) / (3σ)     // 单侧时取对应一侧
MRi   = |xi - x(i-1)|
MRbar = ΣMRi / (n - 1)
CL    = mean
UCLx  = mean + 2.66 × MRbar
LCLx  = mean - 2.66 × MRbar
UCLmr = 3.267 × MRbar
```

边界：n < 2 只返回均值；σ = 0 时不计算 Cp/Cpk，控制限退化为均值线，
避免"数据完全不变 → 所有点越限"的误判。

判异输出结构：`outOfControl`（越限点下标）+ `violations`（可读文本，含点位区间）。

## 12. 合格证标签与 SPC 联动停线（P1）

### 12.1 标签生成

```
输入：path, station(label.*), sn, product, orderNo, operator, shift, finishedAt
输出：PDF（页宽/页高 = label.widthMm / label.heightMm）
```

- `QPdfWriter + QPainter`：自定义 `QPageSize(QSizeF(w,h), Millimeter)`，600 dpi，2mm 页边距；
- 排版按页高比例：公司/标题 2~12%，SN 14~38%，产品/工单 40~63%，时间/检验员 64~84%，PASS 右下；
- 文件名：`<SN>_<yyyyMMdd_HHmmss>.pdf`，SN 中的非法字符替换为 `_`；
- 目录：`label.directory`，为空则 `%APPDATA%/AegisLab/AegisHMI/labels`；
- 生成前探测可写、生成后校验非空；失败返回原因，界面只提示不改判定。

### 12.2 SPC 联动判定

```
for each measure step with (hasMin || hasMax):
    points = spcPoints(order, flowId, stepId, 100)
    if points.size() < spc.minSamples: continue
    result = quality::compute(values, hasUsl, usl, hasLsl, lsl)
    if result.hasCpk && result.cpk < spc.cpkThreshold:
        detail = "过程能力不足：<step> Cpk=<x>（阈值 <t>，n=<n>）"
        lockStation(...)
        break
```

- 仅当 `spc.andonOnCpk=true` 时执行；与连续 FAIL/FPY 规则互斥触发（先命中者写事件）；
- 已停线时直接返回，避免重复事件；
- 停线后由看板横幅展示，管理员解除后恢复。

### 12.3 配置增量

| 配置键 | 默认 | 说明 |
|---|---|---|
| `spc.andonOnCpk` | false | 是否启用 Cpk 联动 |
| `spc.cpkThreshold` | 1.0 | Cpk 下限 |
| `spc.minSamples` | 10 | 达到多少样本才判定 |
| `label.enabled` | false | PASS 后是否自动生成标签 |
| `label.directory` | 空 | 空则使用 AppData/labels |
| `label.widthMm` / `heightMm` | 60 / 40 | 标签尺寸 |

## 13. 波形交互、可靠性与运维（P1 收尾）

### 13.1 原始波形捕获与导出

```
[捕获波形…] → captureActive_ = true → onTick 追加 (startSec, samples)
   → 达到 20 秒上限 / 点击"停止并保存"
   → captureReady_ = true → 文件对话框 → CSV
```

- 累积结构：`captureTimes_`（每点显示时间）+ `captureValues_`（行优先，N 通道连续存放）；
- 上限 = `sampleRateHz × 20` 点；到上限自动停止，按钮变为"保存波形…"，用户取消保存可再次点击；
- 切换设备或断线调用 `resetCapture()`，清空缓冲与按钮文案；
- CSV：UTF-8 BOM，表头 `time_s,CH0(mV),CH1(mA),…`，数据行 `时间(6 位小数),值…`；
- 导出成功后日志记录路径、点数与通道数，并清空缓冲（不长期占用内存）。

### 13.2 自动重连

```
closed / failed → scheduleReconnect()
  → 若 !autoReconnect_ 或 manualDisconnect_ 或 reconnectPending_：返回
  → delay = min(16, 1 << min(attempt, 4))   // 1/2/4/8/16 秒
  → QTimer::singleShot(delay, token)
  → 回调：令牌不匹配 / 已手动断开 / 已连接 → 丢弃
  → 否则 ++attempt，reopen() 用上次参数重连
opened → attempt = 0, pending = false, ++token
disconnectDevice → manualDisconnect_ = true, ++token
```

- `reopen()` 按 `mode_` 分派：自定义协议 / Modbus TCP / Modbus RTU / OPC UA，参数取 `last*`；
- 四种协议共用同一套退避与令牌逻辑，避免相互干扰；某协议连接成功会重置计数；
- 日志输出"连接已断开，N 秒后自动重连（第 k 次）"，便于现场判断网络抖动。

### 13.3 通信报文诊断（HEX）

- `DeviceService::setHexLogging(bool)` 控制；界面连接面板提供"HEX 诊断"勾选框；
- 自定义协议：`onBytes` 收到原始字节后输出 `RX: AA 55 …`（前 96 字节）；`sendCommand` 输出 `TX: …`；
- Modbus / OPC UA 有各自的寄存器级日志，不重复输出原始字节；
- 输出走既有 `logMessage` 信号，同屏日志与文件日志都能留存，便于事后排查。

### 13.4 通道校准与日常点检

```
DeviceChannel { gain = 1.0, offset = 0.0, hasCheck, checkValue, checkTolerance }
修正值 = clamp(原始值 × gain + offset, -32768, 32767)   // 采样入环前统一应用
```

- `DeviceService::applyCalibration()` 在 `pushChunk` 前对交错采样逐点修正，波形/摘要/测试看到同一份数据；
- 未校准通道（gain=1、offset=0）直接跳过，不影响性能与旧配置；
- 日常点检：对每个 `hasCheck` 通道 `sampleWindow(ch, 500)` 取均值，判定 `|avg - checkValue| <= checkTolerance`；
- 结果弹窗逐通道列出"实测 / 参考 ± 容差 / 结论"，并写审计（通过与否、操作人、时间）。

### 13.5 班次日报

```sql
SELECT date(r.started_at / 1000, 'unixepoch', 'localtime') AS day,
       COALESCE(NULLIF(r.shift, ''), '未配置') AS shift_name,
       COUNT(*),
       SUM(r.verdict = 'PASS'),
       SUM(r.verdict = 'FAIL'),
       COUNT(DISTINCT r.sn),
       COUNT(DISTINCT CASE WHEN r.verdict = 'PASS' THEN r.sn END)
FROM test_run r
WHERE r.started_at BETWEEN ? AND ? AND (? = '' OR r.work_order = ?)
GROUP BY day, shift_name
ORDER BY day DESC, shift_name ASC;
```

- 产量 = 去重 SN 数，PASS 数 = 首次/任一次 PASS 的去重 SN 数，良率 = PASS 运行数 / 运行数；
- 日报 CSV 列：`日期,班次,运行数,PASS,FAIL,产量,PASS数,良率%`；
- 看板"导出日报"默认统计当天；有当前工单时只统计该工单，无工单时统计全部。

### 13.6 数据库备份与压缩

```cpp
bool SystemRepository::backupTo(const QString& path);  // VACUUM INTO ?
bool SystemRepository::vacuum();                       // VACUUM
```

- 备份生成单文件一致性快照，不中断采集与写入；界面先探测目标目录可写，失败给出原因；
- 压缩回收已删除页的空间，适合归档前或长期运行后执行；
- 两个动作仅管理员可用，成功后写审计（目标路径/结果），失败也写审计。

### 13.7 SN 白名单

```sql
CREATE TABLE IF NOT EXISTS sn_whitelist (
  work_order TEXT NOT NULL,
  sn         TEXT NOT NULL,
  PRIMARY KEY (work_order, sn)
);
```

- 导入：读取文本/CSV 的每一行（忽略空行与首尾空白），单事务 `INSERT OR IGNORE`，返回新增条数；
- 查询：`snWhitelistCount(order)` / `snInWhitelist(order, sn)`；
- 门禁：工单存在清单且 SN 不在清单 → 拒绝开始并提示"该 SN 不在本工单发货清单内"；
- 未导入清单的工单不限制；看板工单信息行显示"SN清单：N 条"。
