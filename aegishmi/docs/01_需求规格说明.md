# 01 需求规格说明（SRS）

> 项目：AegisHMI —— 工业设备自动测试与监控上位机
> 版本：v0.1.0　最后更新：2026-11-25

---

## 1. 背景与目标

工业设备（电源模块、传感器、控制器）出厂前需要做功能测试：上位机连接设备，下发设定值，
采集输出波形，按上下限判定合格与否，并留下可追溯的记录。

目标是做一个**可演示、可维护、有工程深度**的上位机，覆盖 C++/Qt 上位机岗位的核心能力：
多协议通信、二进制协议解析、多线程采集、高性能实时绘图、配置驱动的自动化测试、数据落库。

成功标准：

1. 无真实硬件时，用模拟器即可完整演示"连接 → 采集 → 测试 → 判定 → 导出"闭环；
2. 换测试方案只改 JSON，不改代码；
3. 核心逻辑有单元测试覆盖，关键性能指标可测量、可复现。

---

## 2. 角色与使用场景

| 角色 | 诉求 | 对应功能 |
|---|---|---|
| 测试工程师 | 选择方案、点开始、看每一步结果 | 自动测试页、流程加载、结果表格 |
| 产线操作员 | 只看合格/不合格与 SN | 大字状态、结果落库、CSV 导出 |
| 研发/维护工程师 | 看实时波形、排查通信问题 | 监控页、统计信息、运行日志 |
| 系统集成方 | 对接不同设备/协议 | 自定义协议、Modbus TCP/RTU、OPC UA |

典型场景：

- **S1 实时监控**：连接设备 → 多通道波形滚动显示 → 观察帧率/CRC 错误/丢块。
- **S2 自动测试**：加载 JSON 方案 → 执行 → 每步显示实测值与判定 → 保存并导出。
- **S3 现场排障**：切换协议/站号/波特率，日志定位通信异常。
- **S4 数据追溯**：按时间查历史运行，查看步骤明细，导出 CSV 给质量部门。

## 3. 功能需求

### 3.1 设备连接（FR-C）

| 编号 | 需求 | 验收 |
|---|---|---|
| FR-C1 | 支持 TCP 自定义协议连接（地址 + 端口） | 连接成功状态与按钮文字切换 |
| FR-C2 | 支持 Modbus TCP（地址 + 端口 + 站号） | 每 20 ms 轮询寄存器 0~5 |
| FR-C3 | 支持 Modbus RTU 主站（串口 + 波特率 + 站号） | 每 50 ms 轮询 FC04 |
| FR-C4 | 支持 OPC UA 客户端（端点 URL） | 用 Subscription 订阅 `ns=1;s=Channel0..5`，发布周期 100 ms |
| FR-C5 | 同一时刻只允许一种协议在线，切换前自动断开其它链路 | 连接后参数控件锁定 |
| FR-C6 | 连接失败给出可读原因，不影响程序继续运行 | 日志可见错误文本 |
| FR-C7 | 支持多设备并发（fleet 清单），每台设备独立线程与缓冲 | 2 台设备同时在线，断开一台不影响另一台 |

### 3.2 数据采集与显示（FR-D）

| 编号 | 需求 | 验收 |
|---|---|---|
| FR-D1 | 自定义协议 10 kHz × N 通道接收（N 由设备配置决定，6~64），不丢帧 | 统计面板帧数持续增长，丢块为 0（正常负载） |
| FR-D2 | 帧解码需处理粘包/分包/CRC 错误 | 单测覆盖 |
| FR-D3 | 波形窗口 3 秒、20 fps 刷新、每通道约 900 点 | 长时间运行不卡顿 |
| FR-D4 | 提供通道开关与数值面板（当前值/统计） | 界面可操作 |
| FR-D5 | 显示运行统计：帧数、CRC 错误、采样块、丢块、字节数 | 每秒刷新 |
| FR-D6 | 设备列表切换当前监控设备，波形/统计随之切换 | 切换后波形清空并显示新设备数据 |

### 3.3 命令交互（FR-M）

| 编号 | 需求 | 验收 |
|---|---|---|
| FR-M1 | 支持 SET_VOUT / SET_IOUT / READ_MEASURE / RESET | 模拟器返回正确状态 |
| FR-M2 | 命令有超时；越界值返回状态 1 | 单测 + 集成测试 |
| FR-M3 | Modbus 模式下设定命令映射为 FC06 写寄存器 | 写后回读值变化 |
| FR-M4 | OPC UA 模式下 SET_VOUT/SET_IOUT 映射为写节点 0/1 | 写入后回读值变化 |

### 3.4 自动测试（FR-T）

| 编号 | 需求 | 验收 |
|---|---|---|
| FR-T1 | 从 JSON 加载测试方案，字段错误一次性全部列出 | 非法配置给出字段级错误 |
| FR-T2 | 支持 command / delay / measure 三类步骤 | 示例方案 6 步可跑通 |
| FR-T3 | 支持 `${变量}` 替换 | 单测覆盖 |
| FR-T4 | measure 支持 avg/min/max/peakToPeak 指标与上下限 | 判定结果与实测值一致 |
| FR-T5 | 失败策略 abort / continue、单步重试 retries | 单测覆盖 5 类场景 |

## 5. 边界与不做

- 不做多工位并行测试（单流程串行）；
- 不做线体级多工位汇总/跨工位防重（属于 MES/产线上层系统）；
- SPC 采用单值-移动极差（I-MR）控制图：每件产品一个测量值，不做子组抽样（X̄-R）与自动判稳调限；
- Andon 停线只锁定本工位，不联动声光硬件、不向 MES 下发停线指令；
- 交接班只记录快照与备注，不做班次自动结算/工资工时；
- 不做图形化流程编辑器（手写/复制 JSON）；
- 原始波形只保留最近 20 秒用于捕获导出，不做长时间录制与历史回放；
- 数据库备份/压缩为手动触发，不做定时备份与异地归档；
- SN 白名单按工单本地维护，不与 MES 发货清单自动同步；
- 通道校准为增益/偏置线性修正 + 金样点检，不做多点分段校准；
- 脚本步骤为本地同步执行，不开放文件/网络访问，也不做脚本调试器；
- 不做 Web/云平台、不做域账号/LDAP 等企业统一认证（本地账号即可）；
- 不做物料/上料防错、跨工位在线防重（属于 MES 范畴）；
- MES 仅做结果上传，不做工单/配方下发与停线控制；
- OPC UA 采用订阅接收变化通知；写入仅支持 Double 标量节点，不做服务端方法调用；
- MFC 旧版客户端属于可选项，当前不交付。
